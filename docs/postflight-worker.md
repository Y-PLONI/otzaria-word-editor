# עיבוד שמירה ב־worker

לאחר הייצוא של SuperDoc, בייטי ה־snapshot עוברים ל־worker המשותף עם preflight.
`postflightDocx` נשאר אותו מימוש ובאותו סדר תיקונים; רק מקום ההרצה משתנה.
העלאה ו־commit ממשיכים אחרי סיום העיבוד. כל בקשה מחזיקה worker משלה.

ה־Blob המקורי נשמר. בכשל worker מריצים את המימוש הקיים מקומית; אם הקלט כבר
הועבר, קוראים שוב את אותו Blob. אין ייצוא מחדש של מסמך שייתכן שכבר השתנה.
כשל בתיקון המקומי מחזיר את המקור לפי המדיניות הקיימת.

`reset` ו־`dispose` של מתאם השמירה מבטלים את עיבוד הסבב. נבדק epoch גם לפני
תחילת סבב שהמתין, ואחרי הייצוא. תוצאה שהתיישנה אינה פותחת העלאה ואינה מסמנת
עריכות חדשות כשמורות. כיבוי autosave ו־hold אינם מבטלים שמירה שכבר התחילה.
רק אות הביטול של בעל הסבב קובע ביטול; שם שגיאת קריאה לבדו אינו משנה את מדיניות
ההתאוששות. לייצוא SuperDoc עצמו אין API ביטול, לכן אחרי סיומו האות נבדק שוב.

טיוטות שחזור ממשיכות ב־`postflight:false`. לפני הייצוא נתפסת נקודת שמירה
השייכת ל־Keeper ולדור המסמך שלו. הצלחת snapshot ישן אינה מבטלת את תזמון
הטיוטה של הקלדה מאוחרת, ואינה מעבירה טיוטה חדשה שכבר נכתבה ל־previousDraft.
„שמור בשם” מעדכן את יעד אותה עריכה בתור Keeper, בלי לאפס מונים. טיוטה שנכללה
בשמירה עדיין עוברת לקודמת ללא העתקת בייטים. קבוע ה־MIME הופרד כדי שתבנית
המסמך בזמן build לא תייבא קוד worker של הדפדפן.

## אימות

```sh
npm test -- tests/unit/docx-postflight-worker.test.ts tests/unit/docx-package-worker.test.ts tests/unit/docx-postflight.test.ts tests/unit/docx-export-regressions.test.ts tests/unit/save-coordinator.test.ts tests/unit/session-keeper.test.ts tests/unit/vba-document.test.ts --maxWorkers=1
npm run typecheck
npm run build
node scripts/qa/postflight-worker-qa.mjs --runs 1 --out /tmp/postflight-smoke.json
npm run check:dist
```

## תוצאות האימות

עברו 365 בדיקות ממוקדות, מהן 171 הורצו שוב ב־QA עצמאי, וכן typecheck, בנייה
ו־`check:dist`. [הדוח הגולמי](benchmarks/postflight-worker-8fe0a77.json) מתעד
את גרסת הגשש `8fe0a77` ואת ה־hash של הבנייה. השינוי האחרון בגשש בלבד:
תגובה שגויה או `messageerror` פוסלים מדגם worker גם אם fallback הציל את השמירה.

ב־Chromium 134, דרך `file://`, עברו 12 השוואות פלט בין worker למימוש המקומי:
שלוש חזרות לחבילה ללא תיקון, 5,000 פסקאות, ZIP פגום ו־DOCM של Office. ה־hash,
הגודל וזהות הפלט שלא דרש שינוי תואמים בכל זוג. במדגמים קטנים נמדד גם המחיר
של התנעת worker; אין הנחה שהוא מקצר כל שמירה.

שלושה זוגות הקלדה, CPU×4 ל־renderer בלבד, 1,001 פסקאות ו־12 מקשים בכל ריצה.
כל הזמנים במילישניות; חציון ההמתנה מחושב על 12 המקשים של אותה ריצה:

| זוג | המתנת מקש, מקומי | המתנת מקש, worker | שמירה כוללת, מקומי | שמירה כוללת, worker |
| --- | ---: | ---: | ---: | ---: |
| 1 | 629.2 | 46.3 | 859.7 | 1,239.5 |
| 2 | 851.4 | 54.0 | 1,055.3 | 1,281.2 |
| 3 | 539.0 | 52.9 | 932.3 | 1,792.2 |

כל 36 המקשים במדגמי worker התקבלו במאזין `keydown` במהלך postflight; במסלול
המקומי כולם התקבלו רק אחרי סיומו. בתום כל ריצה אומתו 12 המקשים במודל ובפסקה
הנראית, עם הסמן וזהות המסמך — 72 מקשים בסך הכול. בכל ריצה
נשמר ה־snapshot הישן, ההקלדה החדשה נשארה dirty, והשמירה הבאה כללה אותה.
זמן השמירה הכולל **עלה** במדגם worker: החציון היה 1,281ms לעומת 932ms מקומי.
השיפור הנמדד הוא בזמינות תור הקלט בזמן העיבוד. שלושה זוגות בסביבה משותפת אינם
מוכיחים שיעור שיפור בכל מחשב.

מוני `longTasks` של ההקלדה נשמרו כאבחון בלבד. השמירה הופעלה דרך
`Runtime.evaluate`, שבכיול נפרד נמצא כי הוא עלול להשמיט משימות מן המדידה.
אפס המשימות שדווחו במסלול המקומי אינו הוכחת היעדר חסימה — המקשים אכן המתינו.
אין להסיק ממונים אלה הפחתת חסימה. מדידת החבילה מתחילה אחרי timer, אך גם בה
אפס אירועים אינו הוכחה לשיפור. המתנת הקלט נמדדת בנפרד, כמפורט להלן.

## תחום המדידה

הגשש משווה ב־`file://` את הפלט, זמן העיבוד ו־long tasks עבור חבילה ללא תיקון,
חבילה גדולה, ZIP פגום ו־DOCM של Office. הוא גם פותח מסמך בדיקה במוצר ומקליד
באירועי מקלדת אמיתיים בזמן postflight. נבדקים זהות המסמך הפעיל, יעד בגוף המסמך
וסמן יחיד, הטקסט במודל ובפסקה המצוירת, ה־snapshot שהועלה, dirty אחרי שמירת
snapshot ישן, והשמירה העוקבת.

`--runs` שולט בחזרות; סדר המסלולים מתחלף. `--paragraphs` שולט בבדיקת החבילה;
מסמך ההקלדה מוגבל ל־1,001 פסקאות כדי שפריסת העורך לא תשלוט בניסוי.
`--cpu` מאט את renderer בלבד. זמן ההמתנה של קלט נמדד ממשלוח CDP עד קבלת
keydown. נמדדת בנפרד הזדמנות תזמון של שני rAF אחרי האירוע; היא אינה מוכיחה
שהמנוע כבר החיל את המקש או שהמקש צויר. אימות המודל, הסמן והטקסט המצויר נעשה
בסוף ההקלדה. הדוח כולל חפיפת משלוח/קבלת המקשים ל־postflight, ומפריד זמן שמירה
כולל מזמן postflight וחסימת התהליכון.
לצורך ההשוואה מבוצעות שתי שמירות מפורשות ו־autosave כבוי באותו סשן בדיקה;
טיוטות השחזור נשארות פעילות. כך renderer איטי אינו מוסיף שמירה שלישית למדגם.
בבדיקת המוצר תחום `postflightMs` מתחיל בבניית worker החבילה ומסתיים בבקשת
כרטיס ההעלאה; קריאת ה־Blob שלפניו כלולה בזמן השמירה הכולל, לא בתחום זה.

ההשוואה היא בין worker ל־fallback המקומי של אותו build ב־Chromium headless;
אין בה מדידת Otzaria/Word native. JSON מכיל מדדים, hashes ודגלי אימות ללא תוכן המסמך.
