# פיצול קוד הפתיחה — SuperDoc 2.23

## מה משתנה

`vite.config.ts` מפיק AMD בעל שמות קבועים במפת ה־build. הטוען הפרטי
`scripts/classic-modules.ts` מוסיף תגיות `<script>` רגילות, משתף Promise וייצוא,
ומאפשר ניסיון חוזר לאחר כשל. אין תלות ב־RequireJS, ב־CDN או ב־ESM מ־`file://`.
ייבוא פנימי דינמי של SuperDoc נשמר דרך ה־package הציבורי; הגרסה נשארת `2.23.0`.
`require` עם מערך הוא אסינכרוני; עם שם יחיד הוא מחזיר רק מודול שכבר הוערך,
וזורק מיד עבור שם לא מוכר או שטרם הושלם. כך בדיקת `require('stream', true)`
של JSZip נשארת בתוך ה־`try/catch` שלה ואינה יוצרת דחייה אסינכרונית בלתי מטופלת.

שלוש החלוניות שנדחות הן פתיחת מסמך, ניהול קיצורים וניהול מאקרו. המעטפת ממשיכה
להחזיק את הפקודות, הקיצורים והנתונים; רק התצוגה וה־CSS שלה מיובאים בשימוש הראשון.
המופע נשמר בפתיחות חוזרות, וביטול בזמן טעינה אינו נפתח מחדש עם הגעת הקוד.

PDF.js וה־worker המוטמע שלו נשארים באריזה ומיובאים לפי צורך. מסלול ה־PDF/EMF
של המנוע אינו מושבת. מקורות עובדי המסמך נשארים IIFE בתוך `engine-workers.js`,
והמנוע מקבל כתובות `blob:` של אותם מקורות.

`overrides.pdfjs-dist=5.5.207` מצמיד את API ה־PDF לגרסת ה־worker המוטמע ב־SuperDoc
2.23.0. ה־lockfile הקודם פתר את טווח התלות ל־5.7.284, והציור נכשל על אי־התאמה
מפורשת. [PDF.js דורש התאמה מלאה בין API ל־worker](https://github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions#reasons-for-the-error-the-api-version-abc-does-not-match-the-worker-version-xyz).
בשדרוג SuperDoc יש לעדכן את הזוג יחד ולהריץ שוב את שער ציור הפיקסל.

## מה למדוד

`dist/bundle-report.json` מכיל גדלים בבתים, תלויות ורשימת מודולים לכל chunk.
`entryFiles` הוא הסגור הסטטי של הכניסה; `preloadFiles` מוסיף את מנוע ה־DOCX
ותלויותיו הסטטיות, הנדרשים לפתיחת DOCX. הזיהוי נעשה מ־module metadata בזמן
הבנייה; שם עם hash אינו מקודד מראש. `startupFiles` כולל גם אותם וגם את ה־workers.
הבקשות מתחילות באותו tick בסדר workers → app → preload, אך `preload` רק
רושם הגדרות: ה־factory מופעל רק כש־SuperDoc קורא לייבוא הדינמי הרגיל.
כך קריאת קובץ המנוע אינה ממתינה לסיום הרצת app. PDF והחלוניות נשארים דחויים.
המדידה סוכמת **כל** בקשת סקריפט בפועל, ולא רק את `app.js` או תוכנית ה־build.

האירועים נפרדים: `script:*:start` מציין הזרקת תגית; `script:*:loaded` מציין
שהקובץ נרשם; `module:*:ready` מציין שה־factory והתלויות שלו הורצו. ב־AMD,
`load` לבדו אינו מבטיח שקוד הממשק כבר הופעל. `shellReadyAt` מציין מנוע זמין
ומסך טעינה שהוסר; הוכחת ההקלדה בודקת בנפרד תו באותה פסקה גם במודל וגם בציור.

## תוצאות — 4 בנובמבר 2026

הבסיס הוא `db247ed`, והמוצר הנבדק הוא `64d7c9e`; שניהם עם SuperDoc 2.23.0.
הפלט החדש כולל גם את הצמדת PDF.js לגרסת ה־worker המתוארת לעיל.
[הדוח הגולמי](benchmarks/startup-bundle-2026-11-04.json) כולל את כל הריצות,
בקשות הסקריפטים, גרסאות הדפדפן, גודלי הקבצים ו־SHA-256 של שני הפלטים.

| נתון, בבתים | לפני | אחרי |
| --- | ---: | ---: |
| `engine-workers.js` | 7,097,878 | 7,097,878 |
| `app.js` | 16,578,621 | 2,890,194 |
| מנוע DOCX בקובץ נפרד | כלול ב־app | 11,466,436 |
| **כל סקריפטי הפתיחה בפועל** | **23,676,499** | **21,454,508** |
| `index.html`, כולל הטוען inline | 29,481 | 35,438 |
| **סקריפטי הפתיחה + HTML** | **23,705,980** | **21,489,946** |
| כלל קובצי `dist`, ללא דחיסה | 26,024,466 | 26,085,283 |

החיסכון בסקריפטי הפתיחה הוא **2,221,991 בתים (9.4%)**; כולל HTML הוא
**2,216,034 בתים (9.35%)**. הקוד הדחוי עדיין נארז; כלל קובצי `dist` גדל
ב־60,817 בתים. ה־workers לא שונו.

שלושה זוגות ריצות לסירוגין, בפרופיל חדש של Chrome `157.0.8103.38`, עם האטת
CPU×4 ל־renderer בלבד לפני הניווט. הזמן הוא מהניווט עד שקיים עורך ומסך הטעינה
הוסר (`shellReadyAt`):

| זוג | לפני, שניות | אחרי, שניות |
| --- | ---: | ---: |
| 1 | 10.477 | 7.374 |
| 2 | 6.976 | 8.844 |
| 3 | 33.936 | 10.345 |
| חציון | 10.477 | 8.844 |

החציון במדגם ירד ב־15.6%, אך השונות גדולה, המדגם קטן והסביבה משותפת; גם
הריצה החריגה נשמרה. זהו נתון תיאורי, לא הוכחה להאצה כללית. מטמון הדיסק לא
נוקה בין הריצות, ולא נמדדה כאן השהיה עד ההקשה הראשונה. שער נפרד הוכיח
שהקלדה אמיתית מופיעה גם במודל וגם בפסקה הנראית.

בגרסת ביניים ללא preload עלה החציון מ־7.722 ל־8.992 שניות. היא חשפה שרשרת
בקשות: המנוע התבקש רק אחרי הרצת app. כעת בקשות workers/app/מנוע מתחילות
באותו tick, לפני סיום factory הכניסה.
השער מאמת את סדר הבקשות; נתוני הביניים נשמרו בדוח.

עברו typecheck, בנייה, `check:dist`, 22 בדיקות טוען/Vite בסקירה עצמאית, וכל
8 בדיקות המוצר ב־`file://`. ניסיון בנייה קודם השאיר שני chunks ישנים,
ו־`check:dist` חסם אותם. הפלט הסופי נבנה ישירות ל־outDir חדש: 26 קבצים,
כל ה־hashes אומתו, ללא החרגות או ניקוי ידני של קובצי מוצר.

### עדכון אימות האריזה — 5 בנובמבר 2026

[מאמת ה־SDK הרשמי `64ee7c`](https://github.com/Otzaria/otzaria-plugin-validator/blob/64ee7c7806a03fcba16c111a7b6c3185e4d92804/src/reachability.js) פירש קריאת `new URL(request, module.uri)` בסקריפט
inline כאילו הייתה `url(...)` של CSS והתריע על נכס חסר. הוסר ה־hook המיותר,
ונוסף שער הבנייה המתואר בהמשך. המאמת עצמו ומדיניות האזהרות לא שונו.
בנייה טרייה של `8378e55` עברה את המאמת עם SDK חי ו־`fail-on-warnings`: אפס
שגיאות ואזהרות. נכס חסר אמיתי בעותק בדיקה עדיין יצר אזהרה אחת. עברו גם 24
בדיקות ממוקדות וכל 8 שערי המוצר באופליין; בפלט 26 קבצים, ללא קובצי QA או chunks ישנים.
`index.html` קטן ב־72 בתים ל־35,366; תיקון טוקן הצל שקדם לכך הוסיף 4 בתים ל־app.
[הראיות וה־hashes של הפלט החדש](benchmarks/startup-bundle-sdk-8378e55.json)
נפרדים ממדידות הזמן לעיל, שלא הורצו מחדש ושומרות את ה־SHAs המקוריים.

## שחזור

```sh
npm run typecheck
npm test -- tests/unit/classic-modules.test.ts tests/unit/classic-assets.test.ts tests/component/lazy-panel.test.ts --maxWorkers=1
npm run build
npm run check:dist
CHROME=/path/to/chromium npm run check:bundle -- --out bundle-runtime.json

# כל ריצה משתמשת בפרופיל דפדפן חדש; ההאטה מוחלת לפני ניווט לקובץ.
CHROME=/path/to/chromium npm run check:bundle -- --startup-only --cpu 4 --out after.json
CHROME=/path/to/chromium npm run check:bundle -- --startup-only --cpu 4 --root /path/to/baseline --out before.json
```

לשתי הריצות משתמשים באותו סקריפט בדיקה, דפדפן ודמה של המארח. `--root` מחליף
רק את תיקיית ה־build. אין להריץ מדידות במקביל לבנייה, לבדיקות או לדפדפן נוסף.

## שערי תקינות

- `check:dist`: תחביר classic בלבד, כל התלויות מקומיות ונארזות, הפרדת PDF
  והחלוניות, ובאנרים של רישיונות בכל chunk רלוונטי. תהליך ההפצה אורז את כל `dist`.
- `check:bundle`: פתיחה מ־`file://` והקלדה נראית, היעדר בקשות PDF/חלוניות במסמך
  רגיל, שימוש ראשון וחוזר, כשל קובץ אמיתי וניסיון חוזר, Escape ושחזור פוקוס,
  preload לפני סיום factory הכניסה, וציור פיקסל כחול מ־EMF ומ־PDF כשהרשת כבויה.
  הגשש דורש אישור CDP לפקודות הרשת וגם `navigator.onLine === false` לפני
  טעינת החלוניות, EMF ו־PDF; כשל בהפעלת מצב אופליין מפיל את הבדיקה.
- בדיקות ממוקדות: Rollup ו־Vite אמיתיים, כתובות נכסים בעמוד ובעובד, שיתוף
  בקשות, כשל/timeout וניסיון חוזר, ביטול ופתיחה מאוחרת, והפוקוס בחלון האמיתי.

כתובות נכסי העמוד נפתרות מול `document.baseURI`: Vite מוסיף אותן אחרי ש־Rollup
בחר פרמטרים ל־AMD, ולכן `require.toUrl` חופשי עלול להיות בלתי מוגדר. ה־plugin
מסמן רק chunks של העמוד; בניית worker יורשת את callback ההגדרות אך נשארת
בפתרון המקורי של Vite מול `self.location.href`. הבדיקה כוללת עובד עם נכס משלו.
הטוען אינו מממש `require.toUrl`: אין לו צרכנים בפלט המוצר. שער הבנייה דוחה
הופעת `.toUrl` בפלט הסופי, גם אחרי שינוי שם המקבל. הפקת `ROLLUP_FILE_URL`
ישירות ב־AMD נבדקת ככשל מפורש; נכסי Vite של העמוד וה־worker נבדקים כמסלול תקין.

בדיקת ה־PDF עברה ב־Chrome for Testing `157.0.8103.38`. ה־worker המודרני
המוטמע ב־SuperDoc 2.23 משתמש ב־`Uint8Array.toHex`, שחסר ב־Chromium 134 שהיה
בסביבת הבדיקה. הגייט וההשוואה משתמשים באותו דפדפן עדכני; אין polyfill במוצר.

ב־Chrome 157 נצפתה בהחלפת EMF הודעת browser של `ResizeObserver`, גם בבסיס.
הגשש שומר את האירועים הגולמיים ומסווג רק התאמה מלאה להודעה, שורה 0,
`error=null` וכתובת דף הבדיקה. שגיאות אחרות ודחיות Promise חוסמות; גם הצטברות
חדשה בחלון שקט של 500ms אחרי שני rAF מפילה את השער.

## תחום המדידה

הריצה היא על `dist` בנוי ב־Chromium עם `file://` ודמה של API המארח, ולא שרת פיתוח.
האטת CPU היא הדמיה; היא אינה מדידה של מחשב Windows חלש או של WebView2 בתוך אוצריא.
נתוני גודל מבודדים את שינוי האריזה. זמן הסרת מסך הטעינה כולל גם פתיחת מסמך
ופריסה במנוע, ואינו זמן תגובה להקשה ראשונה. אין להסיק ממנו לבדו על שיפור ההקלדה.
